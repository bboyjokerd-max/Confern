# Tangerine Converter（Windows 初版）人工測試清單

**版本**：M1d／M1e／M1f-lite（第一個「真的會轉檔」的版本）
**日期**：2026-10-01
**目的**：明天你只要照著做，就能判斷這個初版**能不能用**，以及哪裡還不行。

> 這份清單的每一項都寫了「怎麼看結果」。**看到什麼就記什麼**——
> 不確定、時好時壞、看不懂，都是有效結果，比「好像可以」有用得多。

---

## 0. 開始之前

**啟動**（兩種都行）：

1. 雙擊 `tools\start-tangerine.cmd`
2. 或雙擊桌面的 `啟動 Tangerine Converter.cmd`

畫面不會出現任何視窗——這是正常的（本程式沒有主視窗，只在拖曳時出現輪盤）。
若想確認它活著：工作管理員應該看得到 `Confern.exe`。

**日誌**（有問題時看這兩個檔案）：

| 檔案 | 內容 |
|------|------|
| `%LOCALAPPDATA%\Confern\logs\confern.log` | UI 行程：輪盤顯示、放手、轉檔進度 |
| `%LOCALAPPDATA%\Confern\worker.log` | 轉檔行程：每個檔案的解碼／編碼／耗時 |

**怎麼用**：
> 在檔案總管**拖著檔案**的時候**按住空白鍵** → 輪盤在游標處出現 →
> 移到目標格式（或用方向鍵）→ **放開滑鼠**（或按 Enter）→ 檔案就出現在原檔旁邊。

**結束**：工作管理員結束 `Confern.exe`（設定頁已經有了，但**托盤還在待辦 4**，所以目前仍沒有「結束」選項）。

## 1. 核心功能（這幾項沒過就等於不能用）

| # | 做什麼 | 應該看到什麼 | 記什麼 |

## 3. 錯誤處理（訊息要看得懂，且不能無聲無息）

| # | 做什麼 | 應該看到什麼 |
|---|--------|--------------|
| **9** | 同時拖一張 JPG 和一個 PDF | 輪盤顯示「混合選取，請選同類別」，**放手不會轉檔** |
| **10** | 拖一個 PDF | 「不支援的格式」 |
| **11** | 拖一個 `.heic`（手機照片）| 若這台有裝 HEIF 擴充 → 正常轉檔；沒裝 → 明確說「無法解碼」。**請記下實際出現哪一種** |
| **12** | 拖一個壞檔（例如把 .txt 改名成 .png） | `✓ 0 / ✗ 1` 或單獨的失敗訊息，**不會靜靜地什麼都不做** |
| **13** | 拖 3 張同類別圖片批次轉 | 進度**只有一行** `N/M` 原地更新，最後一行 `✓ 3`；**不該出現多個視窗或很多行字** |

## 4. 你最容易感覺到差異的地方

| # | 做什麼 | 為什麼要測 |
|---|--------|-----------|
| **14** | 用手機**直拍**的照片（EXIF 有方向標記）轉成 PNG | 我們實測過：若不做處理，PNG 會是**躺著**的（PNG 檢視器不看 EXIF 方向）。現在應該要**站正** |
| **15** | 批次轉 8 張，其中 2 張故意用壞檔 | 應該顯示 `✓ 6 / ✗ 2`，而且**不會**自動彈出清單干擾你 |
| **16** | 轉檔中看一下 CPU／風扇 | 轉檔在**獨立行程**；轉完應該自己消失（工作管理員不該殘留多個 Confern.exe） |
| **17** | 把一個**很大的圖**（例如 10 MB 以上）轉成 PNG | 記下大概幾秒。我們量到 11.6 MB／20.7 MP → 約 1.3 秒 |

## 附錄 A：兩個一鍵檢查

**殘檔與產物檢查**（把 `<資料夾>` 換成你剛剛轉檔的資料夾）：

```
powershell -ExecutionPolicy Bypass -File tools\check-test-artifacts.ps1 -Folder "<資料夾>"
```

它會列出：`.tmp-*` 殘檔（應該 0 個）、最近的產物、日誌中的轉檔結果與失敗訊息、有沒有殘留行程。

**原檔是否被動到**（對單一檔案，前後各跑一次，兩個雜湊要一樣）：

```
certutil -hashfile "C:\path\to\photo.jpg" SHA256
```

## 附錄 B：已知限制（**明天不用測這些，它們本來就還沒做**）

| 項目 | 狀態 |
|------|------|
| **WebP 輸出** | 只支援 WebP **輸入**（本機沒有 WebP 編碼器，打包 libwebp 是後續工作）。扇區不會出現 WEBP |
| **GIF 輸出** | 規格沒有宣告，所以**刻意不提供**（本機其實做得到，但那是多承諾） |
| **HEIC 輸出** | 不做（不重新散布 HEVC 編碼器） |
| **設定頁（UI）** | **有**：執行 `Confern.exe --settings-ui`（只開設定頁、關掉就結束，不啟動覆蓋層）。也可以直接編輯 `%LOCALAPPDATA%\Confern\settings.json`（見附錄 C）。托盤入口屬待辦 4 |
| **失敗清單展開** | `✓ 8 / ✗ 2` 目前只顯示一行；**點開看清單**還沒做（失敗訊息在日誌裡） |
| **開機自動啟動** | 還沒接上登錄檔 |
| **雲端檔案（OneDrive 佔位檔）** | 有 30 秒逾時保護，但沒有佔位檔可以測 |
| **多螢幕／不同 DPI** | 只在單螢幕 2560×1080 驗過 |
| **輸入法（IME）開啟時按空白鍵** | 還沒做確定性測試，可能被輸入法吃掉 |

## 附錄 C：設定檔（沒有 UI 時的替代）

路徑：`%LOCALAPPDATA%\Confern\settings.json`（不存在時就是用規格預設值）

```json
{
  "JpgQuality": 85,
  "WebpQuality": 85,
  "TriggerKey": "Space",
  "StartWithWindows": true,
  "Language": "system",
  "NamingCollision": "auto-suffix",
  "CaptureTimeoutSeconds": 30,
  "EmergencyHotkey": "Ctrl+Alt+Shift+Q",
  "Diagnostics": false
}
```

超出範圍的值會被夾回允許區間並寫在日誌裡（例如 `JpgQuality` 只允許 60–100）。
檔案壞掉不會讓程式起不來，會退回預設值並說明。

## 附錄 D：怎麼把結果給我

最有用的三種紀錄：

1. **哪一項不過**（寫編號就好）＋你看到什麼。
2. 該次操作的日誌片段：`%LOCALAPPDATA%\Confern\logs\confern.log` 最後 50 行。
3. 如果可以重現：**具體步驟**（拖幾個檔、什麼格式、有沒有按空白鍵）。

## 附錄 E：這次是怎麼被驗證的（誠實說明自動 vs 人工）

| 面向 | 自動驗證 | 人工驗證 |
|------|----------|----------|
| 轉檔正確性（像素、尺寸、命名、不覆寫） | ✅ 有（用檔案本身量，含像素取樣比對） | 需要你確認「體感」 |
| 原檔不變（雜湊＋時間戳） | ✅ 有 | 附錄 A 可自查 |
| 零殘檔 | ✅ 有 | 附錄 A 可自查 |
| EXIF 方向 8 種 | ✅ 有（逐一量尺寸與象限顏色） | **需要你用手機照片確認** |
| 進度顯示（一行、原地更新、2 秒淡出） | ✅ 有（量視窗更新次數與淡出時間） | **需要你確認好看／看得懂** |
| **真實拖曳（滑鼠手勢）** | ❌ **做不到**（需要真的滑鼠拖曳） | **這就是明天要測的第 1～17 項** |
| 不按觸發鍵的零侵入 | 部分（狀態機層級） | 第 6 項 |
