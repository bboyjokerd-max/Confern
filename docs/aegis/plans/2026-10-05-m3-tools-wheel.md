## 1. 為什麼是這一片

M1（M1a–M1f）六個切片全部完成，spec 內的功能清單見底；下一步的功能來源只有 §9.4 保留的兩個擴充點：

| 里程碑 | 內容 | 本切片 |
|---|---|---|
| M2 | 影音／音訊／字幕／壓縮檔／PDF／文字 | **不做**——卡在 ffmpeg 授權決策（§6.4:416：只能 LGPL build 且動態連結，機器上那支 gyan.dev full_build 是 GPL，僅供開發） |
| M3 | 去背、裁切、旋轉、壓縮、合併 PDF、去 metadata、讀 QR | **本切片做第一刀** |

M3 七項的相依盤點：

| 工具 | 需要什麼 | 能不能用現有相依做 |
|---|---|---|
| **旋轉** | WIC `BitmapTransform`／JPEG 無損轉向 | **可以**（`CodecRegistry` 已經在用 WIC） |
| 壓縮 | 現有的 `quality` 參數（JPEG 已在用 85） | **可以** |
| 去 metadata | WIC metadata writer | **可以** |
| 裁切 | **需要新互動**（拖曳裁切框） | 技術上可以，但互動成本高 → 後面的刀 |
| 讀 QR | QR 解碼器 | 需新相依 |
| 合併 PDF | PDF 函式庫 | 需新相依 |
| 去背 | ONNX Runtime ＋ 模型 | 需新相依，§6.4:420 說第三里程碑再查 |

⇒ 第一刀選 **旋轉**：**沒有新相依、沒有授權問題、成果肉眼可見**（圖真的轉了），而且可以用「長寬互換」寫成**客觀斷言**（非方形圖轉 90° 後 W×H 必須對調）。

## 2. 這一刀的範圍

### 做

1. **工具輪盤出現**：拖曳檔案時按住 **`觸發鍵 + Ctrl`**（規格 §9.4:390），輪盤切換成第二層——工具扇區，**圖示在上、文字在下**（`ui-redesign:51`），圓心顯示**當前 hover 的工具名**（不是 `原格式 → 目標格式`）。
2. **`ROTATE` 工具真的作用**：在工具扇區放手 → 產出順時針轉 90° 的檔案（沿用 §5 的寫檔契約：**來源唯讀、原子寫入、不覆寫**）。
3. **單一權威**：新增 `Tools/IToolCatalog` ＋ `ToolCatalog`（比照 `Formats/IFormatCatalog`）——「有哪些工具、工具叫什麼、適用於什麼」只有這一份。UI 不得自己判斷。
4. **只顯示已實作的工具**：第一刀只有 `ROTATE` 一個扇區。**刻意不畫還沒做的工具**——設定頁已經有「存得下但沒生效」的前例，介面不誠實是這個專案明文拒絕的事。扇區數量會隨工具增加而長。

### 不做（明講，避免被當成漏做）

- 不做其餘六個工具（壓縮、去 metadata 等後續各一刀）。
- 不做裁切的互動（拖裁切框是獨立的一片）。
- 不動 M2 影音。
- **不動凍結的視覺設計**：方向 D 配色、`WheelDesign.GlowEnabled=false`、`SectorCornerPx=7`。工具輪盤**沿用**第一層的 `WheelDesign` 與 `WheelGeometry`，不新增色票、不新增圓角值。
- 不改第一層（格式輪盤）的任何行為；不按 Ctrl 時的行為必須**與現在逐位元相同**。

## 3. 架構決定（開工前先定，避免中途改）

### 3.1 工具與格式是兩個目錄，不是一個

`IFormatCatalog` 回答「有哪些目標格式」（`TargetsFor(source)`）。工具的語意不同：工具是「對檔案做一件事」，不是「換成另一種格式」。所以另立 `IToolCatalog`，介面回傳 `ToolDescriptor { Id, LabelKey, IconName, AppliesTo(source) }`。

**為什麼不合併**：合併之後 `WheelPresenter` 就要判斷「這一格是格式還是工具」，那個判斷會散進繪製、命中、鍵盤環狀選取三處——正是本專案一直在消滅的那種多頭權威。

### 3.2 觸發鍵 ＋ Ctrl 的偵測放在 DragDetector，且必須證明「不按 Ctrl 時逐位元相同」

現行 `trigger key` 是單鍵（規格 §8 收窄過）。加上修飾鍵後要小心兩件事：

1. **Ctrl 在 Explorer 是「複製」修飾鍵**——按住 Ctrl 拖曳時 shell 的 drop effect 會變成 copy。工具輪盤放手時的語意**不是**「複製檔案」，所以放手那條路徑必須走工具執行，不得落到 §4.2.3 的 Explorer 語意還原。
2. **迴歸風險**：修飾鍵判斷若寫錯，第一層會跟著變。驗收要有一條斷言證明「同一輪裡，按 Ctrl 走第二層、不按 Ctrl 走第一層」。

### 3.3 工具的執行也走 worker（行程邊界不變）

規格 §9.1 的邊界是「UI 不因轉檔卡住」。旋轉一樣可能卡（大圖），所以走同一條 worker 路徑，協議新增欄位而非新增通道：`job { files, target, quality, op }`，`op` 缺省＝`convert`（既有行為不變）。**`protocolVersion` 必須遞增**，且舊 worker 收到未知 `op` 要**明講拒絕**，不得靜默當成 convert。

## 4. 驗收（可失敗、且不靠自證）

| # | 斷言 | 怎麼讓它紅（假故障） |
|---|---|---|
| T1 | 工具輪盤的扇區數＝`IToolCatalog` 回報的工具數，且每格標籤與目錄一致 | 目錄多加一個工具 → 扇區數不變即紅 |
| T2 | 圓心顯示 hover 中的工具名；hover 離開後不再顯示任何工具名 | 把圓心固定在第一個工具即紅 |
| T3 | 按 `觸發鍵+Ctrl` 出現工具輪盤、不按 Ctrl 出現格式輪盤（**同一輪內各驗一次**） | 把 Ctrl 判斷短路成 true 即紅 |
| T4 | 按住 Ctrl 拖曳並在工具扇區放手 → 產出檔案，且**來源檔的 SHA256／mtime／長度三者不變** | 讓工具寫回來源即紅 |
| T5 | 旋轉輸出的 W×H 與輸入**對調**（用非方形 fixture） | 把旋轉角度改成 0 即紅 |
| T6 | 未選工具就放手（按著 Ctrl 但不在任何工具扇區上）→ **不產生任何檔案、不覆寫任何東西**（§4.2.3 的保底語意） | 讓放手無條件執行第一個工具即紅 |
| T7 | 舊 worker 收到未知 `op` → 明確報錯（不得靜默當成 convert） | 讓未知 op 落到 default convert 即紅 |
| T8 | 不按 Ctrl 的完整一輪：`hit layer`／`visual layer` 的行為與改動前**逐位元相同**（用既有的 m1a S4b 契約） | 在第一層路徑插入任何工具判斷即紅 |

**假故障演練是必要條件**：每一條都要當場量到紅（改壞 → 紅 → 還原 → 綠），不是文字描述。這是 2026-10-02 稽核之後的既定標準。

## 6. 風險與已知缺口

1. **工具輪盤的外觀沒有規格值**：`ui-redesign:51` 只寫「圖示在上文字在下、中心顯示 hover 動作」。尺寸、扇區角度、hover 動畫都得沿用第一層的既有值（`WheelGeometry`／`WheelDesign`），**不得新發明數字**；若真的缺一個值，記進 `WheelDesign` 並在文件寫明來源，不散在繪製碼裡。
2. **圖示**：專案目前沒有圖示資源（設定頁 0 個硬編碼色、0 個文字字面值那條紀律）。第一刀的工具圖示以**程式繪製的簡單線稿**（沿用第一層的繪製風格）為之，不引入圖片資源、不加套件。
3. **Ctrl 與 IME**：`R3`（IME／注音下的觸發鍵）在路線圖裡是 M1f 的未驗項；工具輪盤讓觸發鍵多一個修飾鍵組合，**會擴大那個未驗範圍**。本片不解決它，但要在文件標明未驗。
4. **`op` 的協定相容**：`protocolVersion` 遞增後，同時跑舊 worker 的情境（升級中）要優雅失敗。本片只做「明講拒絕」，不做熱替換。

## 8. 執行計畫（誰跑哪個檔、什麼順序）

### 8.1 只有一個入口：產品本體

| | 檔案 | 說明 |
|---|---|---|
| **產品本體** | `src\Sidecar\bin\Release\net8.0-windows\Confern.exe` | 唯一的程式。UI 與 worker 都是它（兩個行程是正常的） |
| **桌面捷徑** | `桌面\Tangerine Converter.lnk` | 唯一的「正常使用者路徑」——**只有它不帶 `--no-autostart`**，也就是只有它會寫開機啟動 |
| **隔離啟動（測試用）** | `Confern.exe --no-autostart` | 三態旗標的 `null` 值：**完全不碰** `HKCU\...\Run`。所有驗收與你自己試玩都用這條 |
| **驗收套件** | `tools\verify-m1{a,b,c,d,f,g,h}.ps1` | 八套，**一律序列執行**（併跑會互相搶行程與輸入） |

`tools\start-tangerine.cmd` 是舊的啟動腳本，文字與圖示都還指著改名前（待清理，見 §9）。

### 8.2 你要按的（每一刀交付後）

1. 雙擊 `Confern.exe`（或先做 §9 的捷徑，之後用捷徑）——**不要**用桌面捷徑做驗收，它會寫開機啟動。
2. 從 Explorer 拖一張**非方形**圖片（例如 `_S4m_test\source\test-1.png`）。
3. **按住空白鍵 ＋ Ctrl** → 應該出現**第二層輪盤**（只有 `ROTATE` 一格）。
4. 移到 `ROTATE` → **放開滑鼠** → 應該產出轉 90° 的檔案在**同一個資料夾**，而且**原檔完全沒被動到**。
5. 若不按 Ctrl：行為必須與現在**一模一樣**（第一層格式輪盤）。

### 8.3 我跑的（順序固定）

| 順序 | 指令 | 什麼時候能跑 | 為什麼是這個順序 |
|---|---|---|---|
| 1 | `Get-Process Confern \| Stop-Process -Force` | 隨時 | 殘留行程會鎖住 exe，讓建置靜默失敗 |
| 2 | `dotnet build src\Sidecar\Sidecar.csproj -c Release` | 你沒在跑 Confern 時 | 建置要確認 **exe 時間戳有變** ＋ **沒有原始碼比 exe 新** |
| 3 | `verify-m1b.ps1`（輪盤幾何／dump） | 隨時（headless dump，不注入輸入） | 第二層輪盤的**視覺證據**在這裡；`--wheel-dump` 是 UI 唯一可自動化的證據路徑 |
| 4 | `verify-m1d.ps1`、`m1h`、`m1f`、`m1c`、`m1g` | 隨時 | 轉檔契約、藥丸、設定頁、編解碼都不受本片影響，用來**證明沒破壞** |
| 5 | `verify-m1a.ps1` | **只有你離開電腦時** | 它會合成滑鼠與鍵盤（S3 的緊急停用、S4 的真實拖曳） |
| 6 | `tools\obsidian\sync.ps1` | 收工時 | 進度同步到 Obsidian |

### 8.4 每一刀的驗收門檻

- **A 刀**：T1、T2、T3、T8 全綠（含「不按 Ctrl 時逐位元相同」）；m1b 的 dump 顯示第二層輪盤的扇區數＝目錄回報數。
- **B 刀**：T4–T7 全綠，且每一條都有**當場量到的假故障紅燈**（改壞 → 紅 → 還原 → 綠）。
