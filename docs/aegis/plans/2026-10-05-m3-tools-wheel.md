## 1. 為什麼是這一片

M1（M1a–M1f）六個切片全部完成，spec 內的功能清單見底；下一步的功能來源只有 §9.4 保留的兩個擴充點：

| 里程碑 | 內容 | 本切片 |
|---|---|---|
| M2 | 影音／音訊／字幕／壓縮檔／PDF／文字 | **不做**——卡在 ffmpeg 授權決策（§6.4:416：只能 LGPL build 且動態連結，機器上那支 gyan.dev full_build 是 GPL，僅供開發） |
| M3 | 去背、裁切、旋轉、壓縮、合併 PDF、去 metadata、讀 QR | **本切片做第一刀** |

M3 七項的相依盤點：

| 工具 | 需要什麼 | 能不能用現有相依做 |
|---|---|---|
| **旋轉** | WIC `BitmapTransform`／JPEG 無損轉向 | **可以**（`CodecRegistry` 已經在用 WIC） |
| 壓縮 | 現有的 `quality` 參數（JPEG 已在用 85） | **可以** |

| 裁切 | **需要新互動**（拖曳裁切框） | 技術上可以，但互動成本高 → 後面的刀 |
| 讀 QR | QR 解碼器 | 需新相依 |
| 合併 PDF | PDF 函式庫 | 需新相依 |
| 去背 | ONNX Runtime ＋ 模型 | 需新相依，§6.4:420 說第三里程碑再查 |

⇒ 第一刀選 **旋轉**：**沒有新相依、沒有授權問題、成果肉眼可見**（圖真的轉了），而且可以用「長寬互換」寫成**客觀斷言**（非方形圖轉 90° 後 W×H 必須對調）。

## 2. 這一刀的範圍

### 做

1. **工具輪盤出現**：拖曳檔案時按住 **`觸發鍵 + Ctrl`**（規格 §9.4:390），輪盤切換成第二層——工具扇區，**圖示在上、文字在下**（`ui-redesign:51`），圓心顯示**當前 hover 的工具名**（不是 `原格式 → 目標格式`）。
2. **`ROTATE` 工具真的作用**：在工具扇區放手 → 產出順時針轉 90° 的檔案（沿用 §5 的寫檔契約：**來源唯讀、原子寫入、不覆寫**）。
3. **單一權威**：新增 `Tools/IToolCatalog` ＋ `ToolCatalog`（比照 `Formats/IFormatCatalog`）——「有哪些工具、工具叫什麼、適用於什麼」只有這一份。UI 不得自己判斷。
4. **只顯示已實作的工具**：第一刀只有 `ROTATE` 一個扇區。**刻意不畫還沒做的工具**——設定頁已經有「存得下但沒生效」的前例，介面不誠實是這個專案明文拒絕的事。扇區數量會隨工具增加而長。

### 不做（明講，避免被當成漏做）

- 不做其餘六個工具（壓縮、去 metadata 等後續各一刀）。
- 不做裁切的互動（拖裁切框是獨立的一片）。
- 不動 M2 影音。
- **不動凍結的視覺設計**：方向 D 配色、`WheelDesign.GlowEnabled=false`、`SectorCornerPx=7`。工具輪盤**沿用**第一層的 `WheelDesign` 與 `WheelGeometry`，不新增色票、不新增圓角值。
- 不改第一層（格式輪盤）的任何行為；不按 Ctrl 時的行為必須**與現在逐位元相同**。

## 3. 架構決定（開工前先定，避免中途改）

### 3.1 工具與格式是兩個目錄，不是一個

`IFormatCatalog` 回答「有哪些目標格式」（`TargetsFor(source)`）。工具的語意不同：工具是「對檔案做一件事」，不是「換成另一種格式」。所以另立 `IToolCatalog`，介面回傳 `ToolDescriptor { Id, LabelKey, IconName, AppliesTo(source) }`。

**為什麼不合併**：合併之後 `WheelPresenter` 就要判斷「這一格是格式還是工具」，那個判斷會散進繪製、命中、鍵盤環狀選取三處——正是本專案一直在消滅的那種多頭權威。

### 3.2 觸發鍵 ＋ Ctrl 的偵測放在 DragDetector，且必須證明「不按 Ctrl 時逐位元相同」

現行 `trigger key` 是單鍵（規格 §8 收窄過）。加上修飾鍵後要小心兩件事：

1. **Ctrl 在 Explorer 是「複製」修飾鍵**——按住 Ctrl 拖曳時 shell 的 drop effect 會變成 copy。工具輪盤放手時的語意**不是**「複製檔案」，所以放手那條路徑必須走工具執行，不得落到 §4.2.3 的 Explorer 語意還原。
2. **迴歸風險**：修飾鍵判斷若寫錯，第一層會跟著變。驗收要有一條斷言證明「同一輪裡，按 Ctrl 走第二層、不按 Ctrl 走第一層」。

### 3.3 工具的執行也走 worker（行程邊界不變）

規格 §9.1 的邊界是「UI 不因轉檔卡住」。旋轉一樣可能卡（大圖），所以走同一條 worker 路徑，協議新增欄位而非新增通道：`job { files, target, quality, op }`，`op` 缺省＝`convert`（既有行為不變）。**`protocolVersion` 必須遞增**，且舊 worker 收到未知 `op` 要**明講拒絕**，不得靜默當成 convert。

## 4. 驗收（可失敗、且不靠自證）

| # | 斷言 | 怎麼讓它紅（假故障） |
|---|---|---|
| T1 | 工具輪盤的扇區數＝`IToolCatalog` 回報的工具數，且每格標籤與目錄一致 | 目錄多加一個工具 → 扇區數不變即紅 |
| T2 | 圓心顯示 hover 中的工具名；hover 離開後不再顯示任何工具名 | 把圓心固定在第一個工具即紅 |
| T3 | 按 `觸發鍵+Ctrl` 出現工具輪盤、不按 Ctrl 出現格式輪盤（**同一輪內各驗一次**） | 把 Ctrl 判斷短路成 true 即紅 |
| T4 | 按住 Ctrl 拖曳並在工具扇區放手 → 產出檔案，且**來源檔的 SHA256／mtime／長度三者不變** | 讓工具寫回來源即紅 |
| T5 | 旋轉輸出的 W×H 與輸入**對調**（用非方形 fixture） | 把旋轉角度改成 0 即紅 |
| T6 | 未選工具就放手（按著 Ctrl 但不在任何工具扇區上）→ **不產生任何檔案、不覆寫任何東西**（§4.2.3 的保底語意） | 讓放手無條件執行第一個工具即紅 |
| T7 | 舊 worker 收到未知 `op` → 明確報錯（不得靜默當成 convert） | 讓未知 op 落到 default convert 即紅 |
| T8 | 不按 Ctrl 的完整一輪：`hit layer`／`visual layer` 的行為與改動前**逐位元相同**（用既有的 m1a S4b 契約） | 在第一層路徑插入任何工具判斷即紅 |

**假故障演練是必要條件**：每一條都要當場量到紅（改壞 → 紅 → 還原 → 綠），不是文字描述。這是 2026-10-02 稽核之後的既定標準。

## 6. 風險與已知缺口

1. **工具輪盤的外觀沒有規格值**：`ui-redesign:51` 只寫「圖示在上文字在下、中心顯示 hover 動作」。尺寸、扇區角度、hover 動畫都得沿用第一層的既有值（`WheelGeometry`／`WheelDesign`），**不得新發明數字**；若真的缺一個值，記進 `WheelDesign` 並在文件寫明來源，不散在繪製碼裡。
2. **圖示**：專案目前沒有圖示資源（設定頁 0 個硬編碼色、0 個文字字面值那條紀律）。第一刀的工具圖示以**程式繪製的簡單線稿**（沿用第一層的繪製風格）為之，不引入圖片資源、不加套件。
3. **Ctrl 與 IME**：`R3`（IME／注音下的觸發鍵）在路線圖裡是 M1f 的未驗項；工具輪盤讓觸發鍵多一個修飾鍵組合，**會擴大那個未驗範圍**。本片不解決它，但要在文件標明未驗。
4. **`op` 的協定相容**：`protocolVersion` 遞增後，同時跑舊 worker 的情境（升級中）要優雅失敗。本片只做「明講拒絕」，不做熱替換。

## 8. 執行計畫（誰跑哪個檔、什麼順序）

### 8.1 只有一個入口：產品本體

| | 檔案 | 說明 |
|---|---|---|
| **產品本體** | `src\Sidecar\bin\Release\net8.0-windows\Confern.exe` | 唯一的程式。UI 與 worker 都是它（兩個行程是正常的） |
| **桌面捷徑** | `桌面\Confern.lnk` | 唯一的「正常使用者路徑」：**直接指向 `Confern.exe`、不經 `.cmd`**，所以只有它會套用 `StartWithWindows`。2026-10-05 改名（原 `Tangerine Converter.lnk`）並修好壞掉的圖示（原本指著已不存在的 `Sidecar.exe`） |
| **隔離啟動（測試用）** | `Confern.exe --no-autostart` | 三態旗標的 `null` 值：**完全不碰** `HKCU\...\Run`。所有驗收與你自己試玩都用這條 |
| **驗收套件** | `tools\verify-m1{a,b,c,d,f,g,h}.ps1` | 八套，**一律序列執行**（併跑會互相搶行程與輸入） |

`tools\start-tangerine.cmd` 是舊的啟動腳本，文字與圖示都還指著改名前（待清理，見 §9）。

### 8.2 你要按的（每一刀交付後）

1. 雙擊 `Confern.exe`（或先做 §9 的捷徑，之後用捷徑）——**不要**用桌面捷徑做驗收，它會寫開機啟動。
2. 從 Explorer 拖一張**非方形**圖片（例如 `_S4m_test\source\test-1.png`）。
3. **按住空白鍵**（觸發鍵）＋ 拖曳 → 出現**第一層格式輪盤**。
4. **按著 Shift** → 輪盤**當場**換成第二層（只有 `ROTATE` 一格）；**放開 Shift** → 切回格式層。
   （2026-10-05 起改為即時切層，原本的 `空白鍵 ＋ Ctrl` 作廢，見 §10.1。）
5. 用**方向鍵**選（或移動滑鼠），按 **Enter** 提交 → 應該產出轉 90° 的檔案在**同一個資料夾**
   （或設定的輸出資料夾），而且**原檔完全沒被動到**。
6. 不按 Shift：行為必須與現在**一模一樣**（第一層格式輪盤）。
   ⚠ **修正（2026-10-05）**：本節原本寫「放開滑鼠」提交——**錯的**。實際的提交鍵是 **Enter**
   （`HandleWheelKey` 的 `VK_RETURN`）；方向鍵負責選擇、Esc 負責取消。這一條是照著程式碼
   重新核對後改的：文件寫錯會直接誤導下一個接手的人。

### 8.3 我跑的（順序固定）

## 10. 決策（2026-10-05，使用者裁定）

兩件都是**產品決定**，不是實作細節，所以**先改規格再改程式**（規格見 §9.4 改寫與新增的 §9.5）。

### 10.1 第二層的啟動方式：`Ctrl` → **`Shift`**，而且改成**即時切層**

| | 舊（`觸發鍵 + Ctrl`） | 新（Shift 即時切層） |
|---|---|---|
| 按法 | 三個同時按（觸發鍵＋Ctrl＋拖曳） | 觸發鍵＋拖曳；想切層再按 Shift |
| 時機 | 必須在輪盤**顯示之前**就按著 | 輪盤顯示**期間**隨時可切 |
| 漏掉的後果 | 畫面沒有任何跡象，使用者只會以為功能壞了 | 這個狀態不存在：沒按就是格式層 |

使用者原話：「邊按著空白鍵再按 Ctrl 滿難按的，而且一不小心第二層就按不出來」。
這不是妥協，是修掉一個真的會讓人以為功能壞掉的設計——我上一輪驗證時也發現那個時間窗口很脆。

**不做**的兩個選項與理由：改右鍵（手感取決於拖曳時的握法，而且要多驗一條「OLE 拖曳期間
按鍵狀態」的路徑）；把預設層直接設成工具層（少一個開關，但格式轉換是九成的使用情境，
改預設會讓常見路徑變複雜）。

### 10.2 輸出位置：預設來源旁邊 ＋ **目的地看得見** ＋ 可設定輸出資料夾

詳見規格 §9.5。核心取捨：**「拖到哪就放哪」做不到**——OLE 拖曳不攜帶目的地，檔案從來沒有真的
被放進目標資料夾（拖曳已經被借去當手勢了），所以那只能是**推測**，而且我們自己的輪盤視窗
就擋在游標底下。推測失敗的代價（檔案出現在你沒預期的地方）比固定規則更糟，所以不做。
取而代之：固定規則 ＋ 可設定 ＋ **在輪盤上把目的地說出來**（那是使用者按 Enter 前唯一會看的畫面）。

### 10.3 實作切片（照這個順序）

| 切片 | 內容 | 為什麼在這個順序 |
|---|---|---|
| **A2** | Shift 即時切層：顯示前判定 ＋ 顯示期間輪詢切換 ＋ `wheel layer switch:` 一行證據 | 使用者立刻感覺得到；不動協議、不動設定檔、不動設定頁 |
| **C1** | `Settings.OutputFolder`（來源旁邊／桌面／指定）＋ 設定頁欄位 ＋ 持久化 | 要動設定檔與設定頁，先讓 A2 站穩 |
| **C2** | `NamingPolicy.ResolveOutputPath(source, ext, targetDirectory)`；null＝現行行為 | 輸出路徑的唯一擁有者仍然只有 `NamingPolicy`——**不得**出現第二個決定輸出路徑的地方 |
| **C3** | 目的地經由 worker 傳遞（job 訊息加 `outputDir`，`WorkerProtocol.Version` 升到 3）＋輪盤顯示目的地 | 協議升級必須跟 C1/C2 一起落地，否則會出現「UI 有設定、worker 不知道」的半套狀態 |
| **D** | 把今天的量測變成套件斷言 ＋ 假故障演練（改壞→紅→還原→綠） | 今天所有證明都是一次性的，不進套件就會退化 |

### 10.4 工具 ②「去 metadata」：兩條路徑，走哪一條由容器決定（2026-10-06）

規格已先寫（§9.4）。這裡記的是**被拒絕的選項**與量到的數字。

| 選項 | 裁定 | 理由 |
|---|---|---|
| 全面重編碼（＝照工具①的字面形狀做） | **否** | 當場量到：Q100 的 JPEG 重編碼改動 48×28 那張圖 5376 個位元組裡的 **949** 個、單通道最大差 **3** ⇒ 達不到「像素完全相同」這條斷言，而 EXIF 只長在 JPEG 上 |
| 全面容器手術（JPEG＋PNG＋WebP 都自己解容器） | **否** | PNG／WebP 的解析在驗收上沒有好處（無損容器走重編碼就已逐像素相同），只是多兩個要保養的解剖器 |
| WIC 壓縮域轉碼（`BitmapEncoder.CreateForTranscoding`） | **否** | 2026-10-06 查證：.NET 8 的 WPF `PresentationCore` **沒有**這個 API（ref `8.0.31` 與 runtime `8.0.6` 兩份組件都查過字串）。要走得自己接 `IWIC*`，那是新的一條寫檔路徑 |
| **JPEG 走容器層移除、其他格式走重編碼** | **是** | 兩邊都當場可量：JPEG 的掃描資料一個位元組都不動 ⇒ 位元組級的保證；其餘格式沿用既有路徑，無損容器逐像素相同 |
| 只去 EXIF、保留 ICC | **否** | 去識別化的場合 ICC 與 EXIF 同等級；而且「保留什麼」需要一個介面，會與品質設定搶位置 |

## 11. 追加切片：工具 ②「去 metadata」（`strip-metadata`，2026-10-06）

規格裁定見 §9.4 的新增條目。範圍寫法沿用 §2。

### 做

1. **工具目錄增加第二格**：`ToolCatalog` 加 `strip-metadata`／扇區標籤 `CLEAN`／新圖示
   `ToolIcon.StripMetadata`（線稿、程式繪製，`WheelPresenter.DrawToolIcon` 多一個 case）。
   輪盤的扇區數＝目錄回報的數目，而 `WheelGeometry` 早就對扇區數泛化，所以第二格會自己出現。
2. **`ConversionEngine.StripMetadata(sourcePath, journal, targetDirectory)`**：骨架與 `Rotate90`
   逐項對齊（格式檢查 → `AtomicWriter.Exists` → `ProbeDecode` → `NamingPolicy.ResolveOutputPath`
   → 處理 → `AtomicWriter.Write` ＋ 同一套 3 次重試與同一組錯誤分類），並且接受 `targetDirectory`。
3. **「處理」那一步有兩條，由容器決定**（規格 §9.4）：JPEG 走容器層移除
   （`Formats/JpegMetadataStrip.cs`，掃描資料不動）；其他格式走既有的「解碼 → 丟 metadata →
   以來源格式重編碼」。政策 `CodecRegistry.HasLosslessMetadataStrip(format)`、
   機制在 `Formats/` 底下——格式知識的擁有者仍然只有一個。
4. **worker 協議加 `op=strip-metadata`** 並在 `RunJob` 的 switch 裡派送。
5. **無頭診斷 `--strip-metadata <path>`**，形狀照 `--rotate90`：同一條「設定 → `NamingPolicy` →
   寫檔」的可無頭驗證路徑，輸出資料夾由 `Settings.OutputFolder` 決定。

### 不做

- **不動協議版本**（維持 3）：未知的 `op` 已經會走 `RejectUnknownOp` 具名報錯，舊 worker 收到
  `strip-metadata` 只會**拒絕**，不會靜默做錯事。這與 `op` 缺席語意是 `convert` 的那一次不同——
  那一次舊 worker 會「照做而且做錯」，那才非升版本不可。
- 不做「選擇性保留」（留 ICC 只去 EXIF 之類）。
- 不做 PNG／WebP 的容器手術。
- 不新增設定項：這一刀**沒有旋鈕**，品質固定 100、輸出路徑沿用 §9.5。
- 不動第一層（格式輪盤）；不按 Shift 時必須逐位元相同。
- 不動凍結的視覺設計（方向 D 配色、`WheelDesign.GlowEnabled=false`、`SectorCornerPx=7`）；
  不新增色票、不新增圓角值。
- 不改既有套件（`tools/verify-m1*.ps1`）：把這一刀變成套件斷言是 §10.3 的 **D 切片**，
  今天只留當場量到的證據。
