## 1. 先講最重要的：第一輪的圖有一個會讓薄罩整層消失的 bug（已修）

### 症狀

`--veil=0` 與 `--veil=80` 產出的 PNG **位元完全相同**（SHA256 一模一樣）：

```
veil=0  E8EED84E4676A28D68C66A26B60FBED93FAEAFAE3D5836B63BCC0B4F0820587E
veil=80 E8EED84E4676A28D68C66A26B60FBED93FAEAFAE3D5836B63BCC0B4F0820587E
```

### 機制（兩個原因疊在一起，兩個都修了）

**(a) 合成器的 alpha 語意混用。** 舊 `Compose` 把「薄罩之後剩下的背景比例」`f = 255 - veilA`
同時當成**輸出 alpha**，但它的 RGB 又已經把背景烘進去了（`rgb = 0.2·bg + veil`）。
存圖端（`SaveFrame`）與 DWM 拿到 alpha 都會**再跟同一張桌布合成一次**：

```
out = (0.2·bg + veil) + 0.8·bg = bg + veil      ← 薄罩被精確抵銷
```

也就是說：**第一輪所有「薄罩看起來如何」的結論都不是薄罩造成的**（包含視覺模型對 60 % 的
「dark opaque disc with no glass character」評語、以及 `veil=22 / cream=52` 那組「甜區」推論）。
**時間與記憶體數字不受影響**（它們與 alpha 語意無關），第一輪的量測仍然有效。

**修法（`Compose`）**：把兩種語意拆乾淨——

| 區域 | RGB | alpha | 理由 |
|---|---|---|---|
| 中心鏤空 | 0 | **0** | 真的透明 |
| 玻璃本體（薄罩＋扇區） | 最終外觀（模糊＋薄罩＋扇區都烘進來） | **255** | 玻璃是不透明的；alpha 若小於 255 就會被再合成一次 |
| 圓盤外投影／光暈 | 純圖層：投影＝黑、光暈＝自己的顏色 | 投影強度／光暈強度 | **不烘桌布**，DWM 才會去壓暗**真實**桌面，而不是壓暗一份抓下來就開始過期的舊桌布 |

**(b)（我自己的）參數順序 bug。** 新增的 `ApplyPalette()` 在 `--veil` 之後才跑，把明確的
`--veil=NN` 又蓋回調色盤預設值。修好順序之後才看到 (a) 的真相。
教訓：**明確的 CLI 覆寫一定要在調色盤之後套用**，否則「我改了參數但輸出沒變」會被誤判成程式沒作用。

### 對正式程式的意義（比 bug 本身重要）

`WheelPresenter` 送進 `UpdateLayeredWindow` 的那張點陣圖必須遵守同一條規則：
**凡是 alpha < 255 的像素，RGB 就不可以含有背景**。玻璃區請給 alpha 255、把模糊與薄罩烘進 RGB；
圓盤外的投影／光暈請當成純圖層。否則薄罩會**無聲消失**——而且不會有任何錯誤訊息，
只會「看起來好像有一點透明」，非常難查。

## 2. D「冷鋼薄荷・對比加強」實測（真實 GDI+ 管線輸出，不是模型推估）

新增旗標：`--palette=d`（D 的調色盤）、`--backdrop=dark|light`（合成桌布）、`--sectors=N`、`--blur=NN`。
**預設值完全不變**（cream、真實螢幕、blur 10），第一輪的數字仍可用同一支執行檔重現。

```
GlassSpike.exe --dump-only --palette=d --backdrop=dark  --sectors=3 --blur=17
GlassSpike.exe --dump-only --palette=d --backdrop=light --sectors=3 --blur=17
```

D 的參數：薄罩 `rgba(8,11,15,.80)`、扇區 `rgba(150,180,205,.20)` / `rgba(70,95,118,.13)`、
文字純白、外緣線 `#ADF9EB` @ .55、柔暈 `rgba(163,241,228,.34)`、扇區缺口 2 格 8°/4 格 2°、
blur 半徑 17（三分離 box blur，σ≈18，對應設計稿的 `blur(18px)`）。

| 桌布 | 圓盤平均 | 盤外平均 | 盤/外亮度比 | 扇區填色 | 白字/扇區 WCAG |
|---|---|---:|---:|---|---:|
| 深色 | `#272F39` | `#2D3341` | 0.83 | `#29323D` / `#161E26` / `#2C343D` | **11.8 – 15.6** |
| 淺色 | `#444C54` | `#E5E7EF` | **0.09** | `#485059` / `#343C42` / `#474F58` | **7.7 – 10.5** |

- 淺色桌布下圓盤**仍然是深色**（盤/外亮度比 0.09），白字一律 ≥ 7.7 ≫ 4.5。
- 兩個極端桌布的實測值與解析模型的預測吻合（模型：純白 7.71 / 純黑 14.33）——
  兩條獨立路徑互相驗證，不是同一個算法自己咬自己。
- **視覺模型交叉檢查**（僅當粗略檢查，第一輪已發現它會自相矛盾）：兩張圖都被判為
  「深色毛玻璃、盤內模糊且壓暗、盤外銳利、白字清楚可讀、深淺兩版圓盤一致」。
- 唯一的弱項：**選中/未選的亮度差只有 1.0–1.4**（扇區之間幾乎同亮度）。
  選中狀態靠**薄荷外緣線 + 幾何外擴**表達，不是靠亮度——這與 D2 被否決的結論一致。

## 3. 薄罩掃描：第一輪留下的 §4 難題，用實測回答

`docs/aegis/work/2026-10-01-glass-spike/90-evidence.md` §4 問的是「玻璃一透，背後桌布不受控 →
D 的對比量測是否作廢？」，並給了三條路：(a) 訂不透明度下限 (b) 對最壞桌布各量一次 (c) 只有外緣做玻璃。

實測（D 調色盤、**淺色桌布**、真 GDI+ 輸出、每個值都是重新合成後量到的）：

| 薄罩 | 圓盤平均 | 盤/外亮度比 | 扇區填色 | 白字/扇區 WCAG | 判定 |
|---:|---|---:|---|---:|---|
| 0 % | `#D3DBE6` | 0.88 | `#C9D4DE` | **1.48** | 不可讀 |
| 40 % | `#8B939D` | 0.36 | `#7F8790` | 3.49 | 不及格 |
| 60 % | `#687078` | 0.20 | `#5A626A` | 5.88 | 勉強 |
| 70 % | `#575E66` | 0.14 | `#474F56` | 7.84 | 安全 |
| **80 %（D 現行）** | `#444C54` | 0.09 | `#343C42` | **10.48** | 安全且有餘裕 |

**結論：走 (a)「訂不透明度下限」，下限約 60 %（在最壞的純白桌布上）；D 用 0.80，餘裕充足。**
(b) 的兩種極端桌布也一併量了（第 2 節），(c) 不需要——D 的對比量測**沒有作廢**。

## 4. 代價：薄罩愈厚，毛玻璃的「細節」愈少

同一張抓圖、只差在模糊與否，取「盤內」與「盤外」的平均差（愈大＝底下的細節看得愈清楚）：

| 圖 | 盤內平均差 | 盤外平均差 | 盤內/盤外 |
|---|---:|---:|---:|
| D・深色桌布 | 2.55 | 12.52 | **0.20** |
| D・淺色桌布 | 2.32 | 11.23 | **0.21** |
| cream（薄罩 22 %） | 10.38 | 15.85 | **0.65** |

盤內/盤外 ≈ `1 − 薄罩` ——**薄罩 80 % 的 D，桌布只剩 20 % 的細節透進來**。
這是 D 的取捨：對比穩定換掉玻璃感。要兩者兼得，安全的方向是**提高扇區的不透明度**
（讓扇區本身不吃桌布），而不是降低薄罩——降低薄罩會直接把白字對比壓到 1.5。

> 註：第一輪 REPORT.md 說「圓盤內仍保留約 46 % 的模糊可見度」，那是**修 bug 前**的數字。
> 修正後同一張 cream 圖重測為 0.65（薄罩 22 % 的合理值），46 % 已作廢。

### 8.1 這輪又抓到兩個真 bug（都對正式實作有直接意義）

**(1) 選中扇區的薄荷描邊整條被裁掉。** 互動原型裡選中那一格會**凸出玻璃圓盤 4px**
（SVG 不受玻璃遮罩裁切），但 `Compose` 判斷「盤內」用的是 `rr < Rw`，於是把凸出那圈
（也就是描邊本身）全部當成盤外丟掉。

- 證據：修正前沿 -45° 往外掃，r=333–337 得到 `#37464D`（背景色）＝描邊不存在；
  修正後同一位置是 `#57E8CE`（＝`#5AF2D6` 疊在玻璃上）。
- 修法：盤內半徑改成 `Rw + (有選中 ? SelExpand×Scale : 0)`。安全性：不透明玻璃的條件是
  `盤內 && (薄罩非空 || 扇區非空)`，多出來的環在未選中的方位兩張表都是 0，所以不會誤判成玻璃。
- **對正式實作的意義**：`WheelPresenter` 的分層視窗點陣圖，「不透明區」的判定半徑必須含選中外擴。

**(2) 鍵帽與中文提示被畫布裁掉。** 第一版用硬編 y 值，而輪盤下緣到畫布底部只有
`CaptureSize/2 − Rw`（1× 時 55px），中文「按住觸發鍵」直接被切一半。
改成**由底部往上排版**、空間不夠就自動縮字，並印出版面供核對：
`[layout] 鍵帽 238x81 @(376,833), 說明 @(419,925) 153x41, 輪盤下緣=825, 畫布=990` ✓ 不再裁切。

### 8.2 兩處刻意偏離原型（都是「原型只在深色桌布上看過」造成的）

1. **中文提示改成「暗色描邊＋白色字身」。** 原型的白字 `rgba(255,255,255,.72)` 直接壓在
   淺色桌布上會消失——實測淺色桌布那張，提示區域 714 個取樣點裡只有 53 個是暗的
   （＝只剩陰影，字本身看不見）。描邊後暗點 682／亮點 863，兩張桌布都讀得到。
2. **中心縮圖的山往下移並壓扁，另加一層較亮的後山。** 原型的山頂落在圓心附近，而圓心正好被
   白膠囊蓋住（膠囊高 42px、圓孔直徑 94px），稜線整個被吃掉。移下來之後垂直掃描可見三段：
   `#162338`（遠景）→ `#2D523F`（後山）→ `#1E3A2E`（前山）。

### 8.3 驗證與一則錯誤的視覺模型主張

- 像素驗證：描邊沿圓弧 -85°→-5° 取樣**全部是 `#57E8CE`**（連續完整）；
  選中扇區填色 r=300–322 = `#3F6B7A`（＝設計值）；版面數字見上。
- 視覺模型（僅供參考）說「薄荷描邊只有上半弧清楚、下半弧消失」——**與像素證據不符，該主張錯誤**。
  它同時正確指出：白膠囊蓋住縮圖主體、淺色桌布下整體偏「漂浮」、外圈柔暈在淺色桌布上幾乎失效。
- ⚠ 縮圖內容是**佔位圖**（真實產品會放來源檔的真實縮圖），所以它「像不像山」不影響產品。

### 8.4 留給使用者拍板的設計問題（渲染層面已無 bug）

1. **白膠囊蓋住縮圖主體**：膠囊高 42px、圓孔 94px，佔掉中心一半。要不要縮小膠囊、或讓它有
   一點透明，讓來源縮圖看得出是什麼檔？
2. **外圈薄荷柔暈在淺色桌布上幾乎失效**：整個光暈系統明顯是為深色桌布調的。
3. **選中描邊（`#5AF2D6`）與外緣線（`#ADF9EB` @ 55%）色相太近**：在彩色桌布上「選中」的

## 9. 使用者拍板後的三項調整（第三輪）

使用者 2026-10-01 對 §8.4 三題的裁示：**①「縮小加上一些透明度」②淺色桌布光暈「好」③選中描邊「換個顏色」**。

### 9.1 中心膠囊：縮小 ＋ 半透明

字 22px→17px、padding 8·24→5·16（高度 42px→30px），底色由不透明改為 **alpha 216（0.85）**。
膠囊仍然畫在縮圖**之上**用 SourceOver 合成（縮圖先畫且不透明，所以分層視窗裡 alpha 仍是滿的，
不會出現半透明破洞）。驗證：膠囊中心由純白 `#FFFFFF` 變成 `#DDE0E4`——
縮圖的藍透上來了 ✓ 而深色字 `#0A0F14` 的對比仍有 11:1 以上。

### 9.2 光暈依桌布亮度**自動**切換（不是旗標）

正式程式拿到的是使用者當下的桌面，不會有人告訴它深淺，所以用抓到的畫面平均亮度判斷：

| 桌布平均亮度 | 策略 | 實測 |
|---|---|---|
| > 140 | 深青暈 `(46,120,110)`、強度 ×1.8、投影 130 | 淺色合成桌布 = **235** ✓ |
| ≤ 140 | 維持薄荷亮暈（原型值） | 深色合成桌布 = **53** ✓ |

理由：薄荷亮暈在淺色桌布上等於隱形（外圈與桌布幾乎同亮度）；淺色底要的是「浮起來」的暗暈。
初版用 ×2.6／投影 150，視覺檢查認為像一塊灰髒污 → 調柔為 ×1.8／130。

### 9.3 選中描邊換色（候選三選一，`--selcolor=RRGGBB`）

| 候選 | 色值 | 與外緣線 `#ADF9EB` 的關係 |
|---|---|---|
| 青藍 | `#35D6FF` | 同為冷色、色相只差約 27°（分離度最低） |
| 純白 | `#FFFFFF` | 無色相、純靠明度，但與白色膠囊／白色標籤搶焦點 |
| 琥珀 | `#FFC24D` | 暖色、與薄荷近乎互補（分離度最高，但會為「冷鋼」加入暖色） |

→ **使用者 2026-10-01 選定：琥珀 `#FFC24D`**，已寫成程式預設值（`--selcolor` 仍可覆寫做比較）。
WCAG 對比：琥珀 vs 選中填色 `#3F6B7A` = **3.64:1**（非文字元件門檻 3:1 通過；舊薄荷是 4.2:1，
但舊薄荷與外緣線 `#ADF9EB` 的亮度差只有 1.16:1，琥珀是 1.34:1——真正要解的是「與外緣線混淆」，
那靠色相分離（暖 vs 冷，約 129°）而不是亮度差）。

### 9.4 這輪又抓到兩個真 bug（都跟「外緣」有關）

**(3) 輪盤外緣出現一圈 4px 的透明縫。** §8.1(1) 把「盤內」半徑加大到含選中外擴之後，
那一圈被判成盤內、卻又不是玻璃（薄罩與扇區表都是空的），於是**既沒有玻璃、也沒有投影與光暈**。
- 證據：淺色桌布那張，r=338 是桌布色 `#E7E4EF`，而它的內側與外側都是深色。
- 修法：投影改成「只要 `rr > Rw` 就算」，不再依附 `if/else`；光暈的遮擋改成只看
  **真正的玻璃像素**（`薄罩非空 || 扇區非空`）而不是 `InDisc`。
- 驗證：r=333 由 `#E7E4EF` 變成 `#243C3A` ✓ 縫消失。

**(4) 選中扇區上被橫切一條薄荷外緣線。** 外緣細線原本畫在扇區**之後**，
於是橫跨不透明的選中扇區，與它的描邊之間夾一道填色細縫 → 看起來像兩條線。
原型是 SVG 疊在玻璃之上，**不透明的選中扇區會蓋掉那條線**。
- 修法：兩條外環細線移到扇區**之前**（未選中的扇區是半透明的，線仍透得出來，與原型一致）。
- 驗證：-45° 由內往外掃，r=318–330 全是填色 `#3F6B7A`，r=332–336 是描邊 `#57E8CE`，
  r=338 之後是盤外——中間不再夾線、也不夾填色 ✓
