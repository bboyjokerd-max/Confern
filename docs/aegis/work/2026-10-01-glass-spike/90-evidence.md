## 2. 判定與關鍵發現

**時間不通過（16.660 > 10 ms）、記憶體通過（< 5 MB）。但超標全部來自抓螢幕，且不可優化。**

`--diagnose` 的證據：`BitBlt` 抓 16×16（256 px）= 16.76 ms ≈ 抓 512×512（262144 px）= 16.56 ms → **與面積無關**；四個螢幕位置 16.53–16.65 ms → 與位置無關；`GetDC(NULL)`／`GetWindowDC`／`BitBlt|CAPTUREBLT`／GDI+ `CopyFromScreen` 四條路全部 16.64–16.72 ms；**`DwmFlush()` 單獨呼叫（完全不搬像素）本身就是 16.678 ms**。

16.67 ms 正好是 **60 Hz 的一個 vblank** → 桌面讀像素被**合成器更新週期**綁住，是在等下一個合成週期，不是在搬資料。**不是最佳化能解決的。**

## 3. 由此定案的設計約束（不是建議）

1. **抓螢幕必須移出關鍵路徑**：在**拖曳開始（收到酬載）時抓一次**，且**非同步於背景執行緒**（絕不可擋 UI 執行緒或滑鼠掛鉤——否則會重現「第一個回呼來得太晚」那類時序問題）。輪盤顯示時直接用已備好的點陣圖。應用可控部分僅 3.8 ms，輪盤 100 ms 預算綽綽有餘。
2. **不得每帧重抓螢幕做毛玻璃**：每帧至少 16.67 ms，等於吃掉整個 vblank。
3. **必須保留純色 fallback**：抓螢幕是全鏈路唯一的外部依賴（DRM／安全桌面會失敗）。建議 fallback 外觀＝純色深玻璃、不模糊，且切換不得改變輪盤幾何與對比下限。
4. **veil 與扇區不透明度必須對 D 的調色盤重新推導**：spike 是在「奶油色扇區」前提下掃出 `veil=22% / 扇區 alpha=52%`（80/65/52/40% 四組中唯一同時透出桌布又保住奶油色者）。55–65% 黑幕與奶油色**數學互斥**（60% 黑幕把奶油壓成 `#31363F`）。**但最終方向是 D「冷鋼薄荷」而非奶油色**，這組數字不能直接沿用。

## 4. 新風險：玻璃會讓 D 的對比量測失效（需拍板）

D 方向是以 **WCAG 對比量測**為依據選出的，而那些量測的前提是「輪盤有不透明的固定底色」。**玻璃一透，背後桌布成為不受控背景 → 固定對比保證失效**：同一顆薄荷色扇區壓在純白桌布與純黑桌布上，可讀性可能天差地遠。

三條路，必須在視覺定稿前選一條：

- **(a) 訂不透明度下限**：由 veil 保證輪盤區域的最低有效亮度，代價是玻璃感變弱
- **(b) 對最壞情況桌布各量一次**（純白／純黑），取兩者都能過的參數區間
- **(c) 只有外緣一圈做玻璃**，扇區維持接近不透明（玻璃感最弱但對比最穩）

不選一條，D 的對比量測等於作廢。

## 5. 未驗證（誠實清單）

1. 只在**這一台** 60 Hz 機器量過；120/144 Hz 或其他 GPU 的下限未驗證（推論應同為一個 vblank，但未實測）
2. **深色／淺色桌布可讀性未測**（計畫檔 §4 原本要求兩種各測一次）
3. **`UpdateLayeredWindow` 從未被呼叫**：spike 只合成到普通 `Bitmap`，premultiplied BGRA 餵給分層視窗的**端到端正確性未驗證**
4. DRM／安全桌面的 BitBlt 失敗行為未驗證，fallback 未實作
5. 多螢幕／DPI 縮放未測
6. 50 次緊密迴圈≠「拖曳開始抓一次」的真實情境
7. 正式 2–4 扇區與中文標籤未測（spike 只做 3 格、英文）
8. **「像不像毛玻璃」目前只有視覺模型評語，且該模型在同一張圖上前後矛盾** → **須人眼定案**
9. `UpdateLayeredWindow` 每帧推 330×330 上螢幕的成本未量

## 6. 過程中最有價值的教訓

**unsafe 幾何係數表的元素大小不一致會打穿 managed heap**：`Glow`/`Veil` 宣告為 `byte[330*330]`（1 byte/像素），但 `Blend*` 以 4 byte/像素定址 → `BlendDisc` 寫到 108900 byte 陣列的 byte 435599。症狀極具誤導性：`Precompute()` 完全正常跑完，崩潰發生在**緊接著的第一次 `GC.Collect()`**（`Fatal error. Internal CLR error. (0x80131506)`，堆疊只有 `System.GC._Collect`）。

教訓：**unsafe 指標運算的元素大小必須與陣列宣告一致；這類錯誤只在下次 GC 時爆炸，會讓無辜的步驟看起來像凶手**（最後靠自建 `--minrepro` 最小重現模式定位）。其他坑：`atan2` 回傳 [-180,180] 導致扇區消失（須用相對角取模，且扇區跨 0° 時正規化兩端仍不夠）；BitBlt 不寫 alpha 必須自己補 255；每帧重配置 435 KB 緩衝造成 +6.77 MB 工作集（改為重用後降到 0.36 MB）。
