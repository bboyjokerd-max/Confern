## 1. 目的與定位

### 1.1 問題

Windows 上要轉一個檔案的格式，現行流程是：開程式 → 匯入 → 選格式 → 選輸出路徑 → 匯出 → 找到結果。**六步，跨越兩個視窗。** 使用者當下的意圖（「把這張圖變成 PNG」）從來沒有需要六步。

### 1.2 價值主張

> 拖著檔案的途中按一個鍵，輪盤在游標處彈出，選好放手——檔案就在原地變成你要的格式，原檔不動。

**要解的三件事**（照抄標的產品的真正創新，不照抄它的實作）：

| # | 機制 | 本產品的定義 |
|---|------|--------------|
| 1 | 拖曳中攔截 | 拖曳進行中，按住觸發鍵即在游標處叫出輪盤，**放手在畫面上任何位置都算數** |
| 2 | 就地寫檔 | 輸出寫在原檔旁邊、同主檔名換副檔名；**原檔永不被修改** |
| 3 | 完全離線 | 無網路、無帳號、無遙測。檔案不離開本機 |

### 1.3 成功證據

- 一個「把圖變成另一種格式」的操作，**從放手到檔案出現 ≤ 2 秒**（≤ 5 MB 圖片），且**全程沒有開過任何視窗**。
- 使用者不需要知道輸出在哪裡——它就在原檔旁邊。
- 不按觸發鍵的一般拖曳，行為與未安裝本程式時**完全一致**（零侵入）。

### 1.4 停損條件

- **M0.5 原型證明 C+ 接收層不可行**（見 §9.2）→ 退回浮動接收目標（路線 C），或整案停止。
- 若「任意位置放手」在目標機器上必須靠殼層擴充才能成立 → **本專案不做**（明確接受體感降級為路線 C）。

## 2. 使用者與情境

| 角色 | 情境 | 期待 |
|------|------|------|
| 一般使用者 | 下載了一張 HEIC，要放進只能用 JPG 的表單 | 拖出來、按空白鍵、選 JPG、放手 |
| 辦公室使用者 | 合約 PDF 截圖要轉 PNG 貼進簡報 | 同上，且**不希望檔案被上傳到任何網站** |
| 設計／工程 | 一批 TIFF 縮圖要轉 WebP 上網 | 多選一次拖、同類別批次轉 |
| 隱私敏感者 | 身分證影本、病歷、未公開客戶稿 | 要求可離線驗證（關掉網路仍可用） |

**不是**的對象：需要批次管線、轉檔品質微調、或影音編輯的使用者（見 §3.2 非目標）。

## 3. 範圍

### 3.1 In Scope（第一個里程碑 alpha）

- 觸發鍵叫出輪盤的**拖曳攔截**（§4）
- **圖片**格式互轉（§6）
- 就地寫檔、命名衝突、原子寫入（§5）
- 多檔批次（**限同類別**）
- 設定頁（觸發鍵、命名、開機啟動、語言）
- 逐檔錯誤回報與復原（§7）
- 完全離線可運作

### 3.2 Out of Scope（明示非目標）

| 項目 | 處置 |
|------|------|
| 影音／音訊／字幕／壓縮檔／PDF／文字 | 第二里程碑；本規格僅保留擴充點（§9.4） |
| 去背、裁切、旋轉、壓縮、合併 PDF、去 metadata、讀 QR | 第三里程碑 |
| **PDF → DOCX** | **永久不做**（品質與字型是公認的坑，投報率極差） |
| 取代原檔（覆寫） | MVP 固定不提供；避免不可逆操作的責任 |
| 從瀏覽器／Outlook 拖出的虛擬檔（延遲渲染） | MVP 明確不支援，顯示提示（§7） |
| COM 殼層擴充 / explorer 行程注入（路線 A） | **明確不做**（決策見 §14） |
| 雲端上傳、帳號、同步、遙測 | 永不做 |
| 發行與收費的實作 | 未決，不阻塞實作（§12） |

### 3.3 相容性邊界（不得破壞）

1. **不按觸發鍵的拖曳必須與未安裝時位元級等價**（移動/複製/捷徑語意、資料夾高亮、拖曳殘影）。
2. 不註冊任何全系統常駐的 shell 擴充。
3. 不安裝驅動、不改 explorer 設定。
4. 解除安裝後，系統不殘留註冊項（僅使用者資料夾內殘留設定，且可一鍵清除）。

## 4. 互動設計（核心）

### 4.1 為什麼是「接收層」而不是殼層擴充（機制定義）

Windows 的 OLE 拖放決定「放手落在誰身上」時，以游標下的視窗為目標，並跳過 `WS_EX_TRANSPARENT` 視窗。因此本產品在**拖曳進行中且觸發鍵按著**時，升起一層：

- 每個螢幕一個視窗，覆蓋該螢幕全部工作區
- `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TOPMOST`
- **`SetLayeredWindowAttributes(alpha = 1/255)`**：視覺上等於不可見，但**保留命中測試**
- **絕不加 `WS_EX_TRANSPARENT`**（加了就會被跳過，整個機制失效）

於是使用者放到任何位置都落在本產品身上，我們同時取得 `IDataObject`（`CF_HDROP` = 檔案清單）與 `IDropTarget::DragOver` 的 `grfKeyState`。

`⚠️ 這是本規格最大的未驗證假設，必須由 M0.5 原型證實（§9.2）。`

### 4.2 生命週期狀態機

```
IDLE ──(左鍵按下 且 前景行程=explorer.exe)──▶ ARMED
ARMED ──(位移 > 系統拖曳門檻 且 觸發鍵按住)──▶ CAPTURING
ARMED ──(放開 或 位移未達門檻)──▶ IDLE
CAPTURING ──(收到 DragEnter 且 IDataObject 含 CF_HDROP)──▶ WHEEL
CAPTURING ──(放開觸發鍵 或 mouse-up 或 逾時)──▶ IDLE（收層）
WHEEL ──(方向鍵)──▶ WHEEL（改選）
WHEEL ──(Drop)──▶ RESOLVING ──▶ IDLE（收層）
WHEEL ──(Esc)──▶ CANCELLED ──▶ IDLE（收層 + drop 保底語意，見 4.2.3）
```

**4.2.1 進入 CAPTURING 的守衛**

- 前景視窗行程必須是 `explorer.exe`（涵蓋桌面與所有檔案總管視窗）。非 explorer 的拖曳（Word 選字、視窗搬移、繪圖軟體）一律不觸發。
- 位移門檻取系統值 `SM_CXDRAG` / `SM_CYDRAG`（預設 4 px）。
- 觸發鍵狀態取自**低階鍵盤 hook**（`WH_KEYBOARD_LL`），不依賴前景焦點。

**4.2.2 收起接收層的四層硬保險**（這是本產品最高風險處，必須冗餘）

| # | 條件 | 動作 |
|---|------|------|
| 1 | 任何滑鼠鍵的 `mouse-up` | 立即隱藏全部接收層 |
| 2 | 觸發鍵放開（鍵盤 hook） | 立即隱藏 |
| 3 | 接收層可見時間 > **30 秒**（可設定） | 強制隱藏 + 寫入診斷記錄 |
| 4 | 行程結束 / 當機 | 視窗隨行程消失（作業系統天然保險） |
| 5 | 緊急停用熱鍵（預設 `Ctrl+Alt+Shift+Q`） | 立即隱藏 + 停用攔截直到下次啟動 |

> **驗收**：連續 50 次觸發／放棄循環後，桌面與檔案總管仍可正常點擊、拖曳。任一層保險失效不得造成「桌面點不到東西」。

**4.2.3 放手時未選格式（C+ 的核心代價，必須實作）**

接收層升起後，我們就是 drop 目標。若使用者在未選格式的情況下放手（含放開觸發鍵後才放手），Explorer **不會**執行它原本的移動/複製——**我們必須自己做**：

| 情境 | 我們的行為 |
|------|------------|
| 放手點在同磁碟的資料夾 | 執行**移動**（等同 Explorer 預設） |
| 放手點在**不同磁碟**（含隨身碟） | 執行**複製**（等同 Explorer 預設） |
| 按住 `Ctrl` 放手 | 一律**複製** |
| 按住 `Shift` 放手 | 一律**移動** |
| 放手點不是資料夾（桌面空白、視窗內部等） | 不做任何事，收層 |
| 放手點是另一個程式視窗 | **不做任何事**（不假裝能轉交給該程式），收層 |

`⚠️ 這是 C+ 相對原版最大的體感代價：攔截期間 Explorer 的資料夾高亮與殘影回饋會消失。使用者按住觸發鍵的期間等於「進入轉檔模式」，這是必須在說明中講清楚的設計契約。`

### 4.3 輪盤 UI

| 屬性 | 規格 |
|------|------|
| 觸發時機 | 收到第一個 `DragEnter` 後 **≤ 100 ms** 內顯示 |
| 位置 | 游標 + 偏移 `(+18, +18)` px；不超出該螢幕工作區（自動翻邊） |
| 扇區 | **排除原格式後**的所有可輸出格式（2–7 個）；原格式不出現 |
| 尺寸 | 直徑 220 px（可依 DPI 縮放）；選中扇區外擴 6 px |
| 中心 | 顯示 `原格式 → 目標格式`（如 `HEIC → PNG`） |
| 檔名預覽 | 選中項下方顯示輸出檔名（如 `holiday.png`）；多檔時顯示 `N 個檔案` |
| 未支援 | 若可輸出格式 < 1 → 顯示「此格式無可轉換目標」並允許 Esc |
| 混合選取 | **拒絕**：顯示「混合選取，請選同類別」＋允許 Esc（照抄原版決策） |
| 動畫 | 淡入 120 ms、選中切換 80 ms；`Esc` 立即消失（不等動畫） |
| 拖曳殘影 | **自繪**：游標旁 32 px 半透明檔案卡（因接收層可能蓋住系統殘影） |

**鍵盤操作**（必須完全可用，不依賴滑鼠）

| 鍵 | 行為 |
|----|------|
| 觸發鍵（按住） | 維持輪盤；放開即收起 |
| `←` `→` / `↑` `↓` | 切換扇區（環狀） |
| `Enter` | 立即以當前選項執行（不需放手） |
| `Esc` | 取消：收層 + 執行 §4.2.3 保底語意 |

**滑鼠操作**：輪盤扇區可直接點擊（因為接收層本身可命中）；放手即執行當前選項。

### 4.4 多檔

- 全部同類別 → 套用同一選項，逐檔輸出。
- 混合類別 → 拒絕（§4.3）。
- 進度：輪盤收起的原位置留下一個**原地更新的單行進度**（`N/M`），完成後 2 秒淡出。**不得逐檔另開視窗或逐行洗版。**
- 部分失敗 → 見 §7.3。

## 5. 檔案處理規格

| 規則 | 內容 |
|------|------|
| 輸出路徑 | 與原檔**同一資料夾**（不可設定，MVP） |
| 輸出檔名 | 同主檔名 + 新副檔名（`holiday.heic` → `holiday.png`） |
| 命名衝突 | `holiday.png` 已存在 → `holiday (1).png` → `(2)`…**永不覆寫、永不詢問** |
| 原檔 | **唯讀開啟、永不修改、永不刪除、永不搬移**；時間戳不變 |
| 原子寫入 | 先寫同資料夾的 `<name>.<ext>.tmp-<guid>` → 成功後 rename 為目標名；失敗或中斷則刪除暫存檔 |
| metadata | MVP **原樣保留**（EXIF/ICC/色彩描述檔）；去 metadata 是後續工具 |
| 色彩 | 保留 ICC profile；不支援的 profile 時退回 sRGB 並在診斷記錄標註（不改檔） |
| 唯讀／無權限資料夾 | 明確錯誤（§7），**不得靜默失敗、不得留暫存檔** |
| 長路徑 > 260 字元 | 使用長路徑感知（manifest + `\\?\` 前綴） |
| UNC／網路磁碟／可移除裝置 | 支援；路徑不可用時明確錯誤 |
| 雲端佔位檔（OneDrive 等，`RECALL_ON_DATA_ACCESS`） | 觸發下載並顯示等待狀態；逾時（30 s）→ 明確錯誤 |
| 來源於轉檔中被刪除／鎖定 | 明確錯誤，逐檔回報 |
| `.lnk` 捷徑 | **不轉檔**（視為不支援格式），避免語意歧義 |
| 虛擬檔（`FileGroupDescriptor`，瀏覽器/Outlook 拖出） | **明確不支援** → 提示「請先將檔案存到磁碟」 |
| 大檔 | 串流處理，不整檔載入記憶體 |

## 6. 支援格式矩陣（MVP）

### 6.1 輸入（解碼）

| 格式 | 來源 | 備註 |
|------|------|------|
| JPG / JPEG | 自建（WIC） | — |
| PNG | 自建（WIC） | 含 alpha |
| BMP | 自建（WIC） | — |
| TIFF | 自建（WIC） | 多頁 TIFF 僅第一頁，需提示 |
| GIF | 自建（WIC） | 靜態：僅第一格 |
| WebP | libwebp（BSD） | 含 alpha |
| HEIC / HEIF | **系統 HEIF 影像擴充** | 見 6.3 |

### 6.2 輸出（編碼）

| 格式 | 來源 | MVP 預設 |
|------|------|----------|
| PNG | 自建（WIC） | 無損；預設輸出 |
| JPG | 自建（WIC） | 品質 85（可設定 60–100） |
| WebP | libwebp | 品質 85（可設定） |
| BMP | 自建（WIC） | 32-bit |
| TIFF | 自建（WIC） | 無壓縮 |
| **HEIC 輸出** | — | **MVP 不提供**，見 6.3 |

### 6.3 HEIC 決策（重要）

**本產品不散布任何 HEVC 編解碼器**，理由：HEVC 涉及專利授權池，閉源商業產品內建編碼器有實質法律風險，且 Windows 的 HEIF 支援本來就由系統擴充提供。

| 情境 | 行為 |
|------|------|
| 系統已裝 HEIF 擴充 | HEIC 可作為**輸入** |
| 系統未裝 HEIC 擴充 | 輪盤照常彈出，HEIC 檔案顯示「需要 HEIF 影像擴充」＋「開啟 Microsoft Store」按鈕（以 `ShellExecute` 交由系統開啟；**本程式本身不連網**，也不代為安裝） |
| HEIC 作為輸出 | MVP 不提供（扇區不出現） |

`→ 這是 ADR 訊號（見 §15）。`

## 7. 錯誤處理與復原

### 7.1 失敗模式對照表

| 失敗模式 | 使用者看到 | 復原 |
|----------|------------|------|
| 檔案損壞／無法解碼 | 游標旁紅字「`name.heic` 無法解碼」 | 無副作用，收層 |
| 不支援的格式（含 `.lnk`） | 「不支援的格式」 | 收層 |
| 虛擬檔（瀏覽器拖出） | 「請先將檔案存到磁碟」 | 收層 |
| 無寫入權限／唯讀 | 「無法寫入此資料夾」＋路徑 | 刪除暫存檔 |
| 磁碟空間不足 | 「空間不足」 | 刪除暫存檔 |
| 來源消失（轉檔中被刪） | 「來源檔案已不存在」 | 刪除暫存檔 |
| 輸出被其他程式鎖定（防毒／同步） | 重試 3 次後「檔案被鎖定」 | 刪除暫存檔 |
| 雲端佔位檔下載逾時 | 「雲端檔案下載逾時」 | 不再等待 |
| 行程崩潰／斷電 | 下次啟動時掃描並清除所有 `.tmp-*` 殘檔 + 顯示一次提示 | 自動 |
| **接收層收不回去** | 無 UI（災難情境） | 四層硬保險（§4.2.2） |

### 7.2 不可接受的失敗（視為缺陷）

1. 原檔被修改、被刪、被搬移。
2. 靜默失敗（沒有輸出、也沒有訊息）。
3. 殘留 `.tmp-*` 檔案。
4. 接收層收起失敗，導致桌面無法點擊。
5. 未按觸發鍵的拖曳行為改變。

### 7.3 多檔部分失敗

輪盤收起處顯示單行摘要：`✓ 8 / ✗ 2`，可點擊展開清單（檔名 + 原因）。清單**不自動彈出**，不打斷流程。

## 8. 設定項

| 設定 | 預設 | 範圍 |
|------|------|------|
| 觸發鍵 | **空白鍵** | 空白鍵 / Ctrl+Shift / Shift / 自訂單鍵 |
| 開機啟動 | 開 | 開 / 關 |
| 語言 | 跟隨系統 | 繁體中文 / English |
| JPG 品質 | 85 | 60–100 |
| WebP 品質 | 85 | 60–100 |
| 命名衝突 | 自動編號 `(1)` | MVP 固定，不可改（覆寫／詢問列為未來選項） |
| 接收層逾時 | 30 秒 | 5–120 秒 |
| 緊急停用熱鍵 | `Ctrl+Alt+Shift+Q` | 可改 / 可關 |
| 診斷記錄 | 關 | 開（僅本機檔案，不外傳） |

`⚠️ 觸發鍵可設定 ≠ 可以任意用單一 Shift：設定頁需在使用者選 Shift 時提示「Shift 在檔案總管拖曳時代表移動，可能造成誤操作」。`

## 9. 架構與邊界

### 9.1 行程與模組

```
[UI / HUD 行程]  .NET 8 + WPF（常駐，無主視窗）
  ├─ HookService        低階滑鼠/鍵盤 hook（唯一全域鉤子擁有者）
  ├─ DragDetector       狀態機 §4.2（唯一狀態權威）
  ├─ CaptureLayer       全螢幕接收層（每螢幕一層，唯一建立/銷毀者）
  ├─ WheelPresenter     輪盤 UI（唯一繪製者）
  ├─ NamingPolicy       衝突命名（唯一命名規則權威）
  ├─ SettingsStore      設定持久化
  └─ ProgressPresenter  單行進度
        │  具名管道（版本化 JSON 訊息）
[Worker 行程]（可多實例，工作隔離）
  ├─ JobQueue           並行上限、取消、逾時
  ├─ CodecRegistry      格式 → 編解碼器（擴充點，§9.4）
  └─ FileWriter         原子寫入、暫存清理
```

**邊界契約**

| 契約 | 規則 |
|------|------|
| UI → Worker | 只傳 `{jobId, sourcePaths, targetFormat, quality}` 與控制指令；**不傳 UI 狀態** |
| Worker → UI | `{jobId, status, outputPath?, errorCode?, errorDetail?}` |
| 版本 | 訊息帶 `protocolVersion`；不相容時 UI 重啟 Worker（不得崩潰） |
| 擁有權 | 每個模組**唯一擁有者**；`CodecRegistry` 是唯一格式知識來源，UI 不得自行判斷副檔名 |

### 9.2 M0.5 生死線（實作前置，必須先過）

| 驗證項 | 通過條件 |
|--------|----------|
| `alpha = 1/255` 的 layered 視窗是否仍可被 OLE 拖放命中 | 在桌面、資料夾、另一螢幕放手，**10/10 命中** |
| z-order 與系統拖曳殘影 | 輪盤與自繪鬼影可見；殘影被蓋住可接受（已自繪） |
| 收層可靠性 | 50 次循環後桌面完全可用 |
| 未按觸發鍵的拖曳 | 與未安裝時行為一致 |

**全數通過 → 進入 §4 實作；任一失敗 → 退回路線 C（浮動接收目標），並重新協商 §3.1 的「任意位置放手」。**

### 9.3 效能

| 指標 | 目標 |
|------|------|
| 常駐記憶體 | < 80 MB |
| 接收層升起 | < 30 ms |
| 輪盤首次顯示 | < 100 ms（視窗預先建立，不在拖曳中建立） |
| 5 MB JPG → PNG | < 800 ms |
| 100 檔批次 | 無當機、無殘檔；並行上限 `min(4, CPU/2)` |
| 冷啟動到可用 | < 1.5 s（且因開機啟動，使用者通常不感受） |

### 9.4 擴充點（供第二／三里程碑）

- 新增類別：實作 `CodecRegistry` 的一個 provider，加入格式→處理器的映射。**UI 不應修改**。
- 新增工具（裁切、壓縮、去 metadata）：以「輪盤的第二層（工具輪盤）」擴充，觸發鍵改為 `觸發鍵 + Ctrl`。

## 10. 隱私與安全

- **無網路**：MVP 不含任何 HTTP 客戶端。驗收方式＝斷網可用 + 用防火牆觀察無對外連線。
- **無帳號、無遙測、無崩潰上傳**（診斷記錄僅寫本機，預設關閉）。
- **不以管理員權限執行**（低階 hook 不需要）；不寫 `HKLM`。
- 不讀取與被拖曳檔案無關的資料。
- 輸出寫入前不執行任何來源檔案內容。

## 14. 決策記錄（本次訪談定案）

| # | 決策 | 理由 | 可否推翻 |
|---|------|------|----------|
| D1 | 攔截層以 **C+（全螢幕接收層）** 為首選 | 拿到「任意位置放手」而不需管理員、不進 explorer 行程、不犧牲 MSIX | 可由 M0.5 結果推翻 |
| D2 | **路線 A（COM 殼層擴充）完全不做** | 需管理員、explorer 崩潰風險、與 MSIX 衝突、+3–4 週；且 C+ 可取代 | 需使用者重新拍板 |
| D3 | 路線 C（浮動接收目標）僅作 **C+ 失敗時的保底** | 避免雙 owner | — |
| D4 | 觸發鍵預設 **空白鍵** | Explorer 拖曳時完全不使用空白鍵，零語意衝突 | 可設定，隨時可改 |
| D5 | MVP 只做 **圖片** | C+ 的風險在攔截層，與類別數無關；最窄範圍最快出清風險 | — |
| D6 | 發行與收費 **暫緩** | 不阻塞實作 | — |
| D7 | HEIC **僅輸入、不輸出**，且不散布編解碼器 | HEVC 專利與散布紅線 | 需法務確認後可改 |
| D8 | 混合選取 **拒絕** | 照抄標的產品的正確決策：不存在共同可用的操作集 | — |
| D9 | PDF → DOCX **永久不做** | 投報率極差 | 需使用者重新拍板 |
