# fixtures/rembg — the portrait fixture for `remove-bg`

## What is here

| file | bytes | pixels | sha256 |
|---|---|---|---|
| `real-512.png` | 560,227 | 512×410 | `0368DC37AF8E15DD208AA53A303A4E600D36B6927C8A830B2D0F8433708C3937` |

`real-512.png` is a **512-pixel-wide downscale of a public-domain NASA photograph**:
*File:NASA astronaut Leland D. Melvin with his dogs Jake and Scout.jpg* (Wikimedia Commons,
**public domain** — a work of the U.S. federal government). The original is 4000×3200. The subject
is an astronaut in an orange flight suit, crouching with two dogs, with an American flag and a
shuttle model behind him; the head is near the top of the frame and the top-right corner is clean
studio backdrop.

It is committed (and not generated by a script) because the assertions in section S22 of
`tools/verify-m3d.ps1` are about **where the mask lands**, which is a property of a real face in a
real frame — a synthetic gradient cannot produce a subject, and there is no way to synthesise
"a portrait" reliably without shipping a person's picture.

The **negative** fixture is not here: it is the already-committed
`fixtures/qr/qr-small-in-scene-160.png` (a QR code on a plain backdrop — exactly the kind of picture
a user really does try `remove-bg` on).

## Why the model is NOT here

The model is 12,984,781 bytes (12.98 MB) of binary. It is fetched by
`tools/get-rembg-model.ps1`, which downloads `Xenova/modnet` → `onnx/model_fp16.onnx`
(apache-2.0) and verifies both its length and its sha256 before installing it:

```
tools\get-rembg-model.ps1                 # -> src\Sidecar\bin\Release\net8.0-windows\models\model_fp16.onnx
```

expected sha256 `25F165DA9BFD30830A575F1F0490F1ACD995975CB349BC02F3D79332E1FE5CF6`.
When the model is absent, the S22 checks that need it are reported **INCONCLUSIVE** (exit 3), never
silently green.

## The measured numbers (2026-10-08)

All of these were measured on this machine, on this fixture, with the shipped model. The first
column is the product's own `--remove-bg-inspect`; the second is an **independent** probe
(`%TEMP%\rembgcheck`, a separate program using a different decoder and `int` truncation) reading the
same PNG — two readers agreeing is what makes the numbers evidence rather than self-report.

| quantity | product inspector | independent probe |
|---|---|---|
| alpha min / max / mean | 0.0000 / 1.0000 / 0.5253 | 0.0000 / 1.0000 / 0.5253 |
| fraction opaque (a = 1) | 0.4954 | 0.4954 |
| fraction fully clear (a = 0) | 0.4590 | 0.4590 |
| centre band (middle 40 %) | 0.89 | 0.8923 (and 1.0000 in the middle 20 %) |
| corner TL / TR / BL / BR | — (mean of the four: 0.30) | 0.0017 / 0.0000 / 0.9662 / 0.2643 |
| top band 10 % / bottom 10 % | 0.02 / 0.82 | 0.0188 / 0.8226 |
| left band / right band | 0.38 / 0.03 | 0.3836 / 0.0346 |

Output: `512×410`, 37,595 bytes, `Bgra32`.  The model's mask tensor for this source is `640×512`
(512 shortest edge, divisible by 32).

### What S22 asserts, and why each threshold is safe

| assertion | need | measured | margin |
|---|---|---|---|
| centre band | ≥ 0.80 | 0.89 | the head and chest are here |
| top band | ≤ 0.10 | 0.02 | only hair reaches the top 10 % |
| top-right corner | ≤ 0.05 | 0.0000 | studio backdrop |
| fully-clear pixels | ≥ 0.20 | 0.4590 | a real cutout has real background |

The **bottom-left** corner is deliberately *not* asserted: the astronaut's suit and the dogs really
do occupy it (0.9662), so demanding transparency there would assert something false about this
photograph.

### The negative case

`fixtures/qr/qr-small-in-scene-160.png` through the same model: mask **max=0.1057, mean=0.0001**
(native) and **max=0.0165, mean=0.0001** (resized to a 512 edge). Both are far below the product's
empty-mask thresholds (`max < 0.30` or `mean < 0.02`), so the tool reports
`NoSubjectFound` ("這張圖找不到人像主體，無法去背") and writes **no file**.
