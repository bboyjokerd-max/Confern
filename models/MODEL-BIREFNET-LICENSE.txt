2. HOW THE PRODUCT FINDS IT, AND WHAT HAPPENS WHEN IT IS ABSENT
--------------------------------------------------------------------------------
RemoveBgModel.ResolvePath() resolves the default model as a PREFERENCE ORDER, not
as a single file name:

    <exe folder>\models\ModelBiRefNet_1024x1024_fp16.onnx   <- used when present
                                                              AND its length is
                                                              exactly the measured
                                                              489666272 bytes
    <exe folder>\models\model_fp16.onnx                    <- otherwise (MODNet)

The length check is deliberate: this file is 490 MB and only exists when a
download finished, and a half-downloaded big file must not turn the tool from
"the edges are soft" into "the tool is broken". A file that is present at the
right length but is not a usable ONNX is reported by name (ModelCorrupt, exit 3,
nothing written) rather than silently ignored -- see RemoveBgModel.Check.

Passing --remove-bg-model <path> overrides both and is what the verification
suite uses. With neither file present the tool reports the named state
ModelUnavailable, exit code 3, nothing written, and tells the user to run the
fetch script; it never crashes.
